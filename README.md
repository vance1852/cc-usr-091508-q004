# 载人舱生命保障告警

本项目服务于载人飞行控制中心，处理舱压、二氧化碳和通风设备遥测产生的环境告警。

系统需要区分短暂尖峰与持续恶化，按照飞行阶段和角色提供可执行的处置信息，并保留确认过程。

## 它解决什么问题

轨道日交班时，下一班飞控最怕面对"一个红色图标"：二氧化碳、舱压、循环风扇的
数据按不同延迟到达，短暂遥测尖峰与持续恶化在图标上长得一样，乘组可能因此
收到互相矛盾的操作建议。本模块让交班视图能够回答三个问题：

1. **这条告警由哪些采样形成** —— 每条告警携带完整的形成采样序列
   （`contributing_samples`）、越限区间（设备时钟）、判定所用阈值版本与任务阶段；
2. **当前由谁接管** —— 确认人、接管人、接管时刻，全部来自不可变事件；
3. **距离下一次升级还有多久** —— 升级是纯函数调度，`ns_to_next_escalation`
   给出倒计时，升级历史可完整重建。

## 架构

```
遥测网关 ──▶ IngestTelemetry ─┐
阈值管理 ──▶ ActivateThresholds ┤
任务计划 ──▶ SetMissionPhase    ┤    ┌───────────────────┐
飞控操作 ──▶ Ack/Assign/        ├─▶  │ 事件日志 (SQLite)  │
             AppendEvidence/    │    │ 追加式, 幂等键去重  │
             ResolveAlert      ─┘    └─────────┬─────────┘
                                               │ 顺序重放
                                        ┌──────▼──────┐
                                        │ 确定性引擎    │  纯函数派生状态
                                        └──────┬──────┘
              ┌────────────────┬─────────────┼─────────────┐
        GetHandoverView   ListAlerts   GetEnvironmentStatus  …
        (按角色裁剪: 乘组 / 飞控 / 医学支持)
```

**事件溯源**：所有状态变化（遥测批次、阈值版本启用、任务阶段切换、确认、
接管、证据、解除）都是追加到 SQLite 事件日志的不可变事件。引擎的内存状态
是对日志顺序重放的**纯函数**——相同事件序列必然得到相同的未决告警、升级
历史与确认人。进程中断后重开数据库即可稳定重建。

**双时钟模型**：

| 用途 | 时钟 | 原因 |
|---|---|---|
| 持续窗口、阈值版本选取、任务阶段选取 | 设备采样时钟 `device_time_ns` | 生理/物理过程的持续性只与星上时间有关，不受链路延迟影响 |
| 失联判定、升级计时、告警形成（地面）时刻 | 地面接收/日志时刻 `ground_recv_ns` / `arrival_ns` | "多久没收到帧"是链路属性；升级是地面流程 |

设备时钟允许漂移：每条采样同时携带两个时刻，引擎为每个传感器维护
地面-设备钟差估计（EWMA）用于展示，但**判定逻辑绝不混用两个时钟域**。

## 判定语义

- **持续窗口**：越限须持续 `window_ns`（设备时钟）才形成告警；相邻采样间隔
  超过 `max_gap_ns` 或遇到不适用本规则的任务阶段，窗口中断重计。
  短暂尖峰（如 3s 的 CO2 冲顶）被窗口自然过滤。
- **重复帧**：按（传感器， 星上采样序号）去重，重复帧不参与窗口计算；
  同一内容的批次整体命中幂等键。
- **离线补传**：迟到的帧按设备时钟插入原始序列的正确位置，可补全空洞、
  闭合持续窗口；由此形成的告警，其设备形成时刻是回溯的，地面形成时刻
  是补传批次到达时刻——两者都保留，延迟完全可解释。
- **阈值版本**：每个版本自 `effective_from_device_ns` 起生效；评估某条采样
  永远选用其设备时刻对应的版本。版本时间线单调、禁止追溯性生效，因此
  **旧阈值重放不会改变当时结论**。
- **任务阶段**：规则可限定适用阶段（如睡眠阶段 CO2 红线更严格）；阶段
  时间线同样按设备时钟选取。
- **关联传感器**：传感器组（如 `atmosphere` = CO2 + 舱压 + 风扇）的整体
  状态为：任一必需传感器失联 ⇒ **证据不足**（绝不据此推导环境安全）；
  否则有未解除告警 ⇒ 告警中；否则正常。
- **升级**：未确认告警自形成时刻起按严重度策略逐级升级（红色：5 分钟
  一级，值班飞控 → 值班主任 → 飞行总监），确认后冻结。升级历史是
  （形成时刻， 确认时刻， 策略）的纯函数，重放必然一致。

## 告警生命周期

```
OPEN ──Ack──▶ ACKED ──Resolve(附解除证据)──▶ RESOLVED
 │              │                                 │
 │              └──Assign 交班接管 (OPEN/ACKED 均可)
 └──未确认期间按策略逐级升级
```

- 告警**不可删除**；服务根本不提供删除接口。
- 红色告警必须先确认（Ack）才能解除（Resolve）；解除必须附解除证据摘要。
- 解除后仍允许 `AppendEvidence` 追加补充证据（只追加，不修改）。
- 所有操作请求携带幂等键：网络重试安全返回成功，不会重复改变状态。

## 角色字段矩阵

`GetHandoverView` / `GetAlert` / `ListAlerts` 按 `RequestMeta.role` 裁剪：

| 字段 | 飞控 | 医学支持 | 乘组 |
|---|:-:|:-:|:-:|
| 告警标识/严重度/状态/摘要/乘组程序 | ✓ | ✓ | ✓ |
| 越限区间、形成时刻（设备时钟） | ✓ | ✓ | ✓ |
| 形成采样明细 | ✓ | ✓（暴露评估） | 仅计数 |
| 峰值/末值 | ✓ | ✓ | — |
| 阈值版本 | ✓ | — | — |
| 确认人/接管人/解除人姓名 | ✓ | 仅角色 | 仅角色 |
| 升级历史/下次升级时刻 | ✓ | — | — |
| 证据条目（操作者脱敏） | ✓ | ✓ | ✓ |
| 传感器组状态（含证据不足） | ✓ | ✓ | ✓ |

未声明角色的请求按最保守（乘组）视图处理。

## 快速开始

```bash
# 运行测试 (含全部确定性重放测试)
go test ./...

# 运行情景演示: 时钟漂移 + 重复帧 + 进程中断 + 离线补传
go run ./cmd/lsdemo

# 启动服务 (空库自动播种在轨默认阈值与 ON_ORBIT 阶段)
go run ./cmd/lifesupportd -db lifesupport.db -addr :50051
```

`lsdemo` 会执行一段 6 分半钟的脚本化事件流：正常遥测 → CO2 尖峰（不告警）
→ CO2 持续超限（红色告警）→ 重复帧重传 → 确认与交班接管 → 风扇失联
（证据不足）→ 离线补传（补出风扇红色告警）→ 追加证据解除 CO2 告警 →
启用更严格的 v2 阈值。同一事件流跑两遍：一遍连续，一遍在第 130 步后
关闭数据库模拟进程中断再续传，最后逐字节对比派生状态并打印三种角色的
交班视图。

## API 概览

| RPC | 说明 |
|---|---|
| `IngestTelemetry` | 遥测批次入库（幂等键 + 帧级去重），返回新形成告警 |
| `ActivateThresholds` | 启用阈值版本（时间线单调，禁止追溯） |
| `SetMissionPhase` | 切换任务阶段 |
| `AckAlert` / `AssignAlert` | 确认 / 交班接管 |
| `AppendEvidence` / `ResolveAlert` | 追加证据 / 附证据解除 |
| `GetAlert` / `ListAlerts` | 告警查询（按角色裁剪） |
| `GetHandoverView` | 交班视图：形成采样、当前接管人、升级倒计时 |
| `GetEnvironmentStatus` | 传感器组状态（正常/告警中/证据不足） |

proto 定义见 `proto/lifesupport/v1/lifesupport.proto`；重新生成代码：

```bash
mkdir -p gen && protoc -I proto \
  --go_out=gen --go_opt=module=lifesupport/gen \
  --go-grpc_out=gen --go-grpc_opt=module=lifesupport/gen \
  lifesupport/v1/lifesupport.proto
```

## 确定性论证与测试

`internal/engine/replay_test.go` 构建一条含时钟漂移（2ms/s）、重复帧、
离线补传、确认/接管/解除、阈值版本切换、任务阶段切换的 39 事件流，然后：

- `TestReplayDeterminismEverySplitPoint`：在**每一个**事件之间模拟进程
  崩溃-重启（40 个切分点），终态快照与连续运行逐字节一致；
- `TestReplayFromLogOnly`：全部事件入库后单纯重放日志，状态一致；
- `TestReplayContents`：对参考运行做内容级断言（告警数、确认人、接管人、
  升级级别、阈值版本归属），防止"一致但错误"。

`internal/server/server_test.go` 通过 bufconn 做 gRPC 端到端验证：
角色字段裁剪、幂等重试、进程重启后交班视图一致。

## 已知限制（后续工作）

- 采样与告警状态全量驻留内存，评估为每帧 O(样本数)；任务级部署应加
  保留窗口与增量评估。SQLite 事件日志仍是唯一事实来源。
- 升级通知目前只有派生时间表；接入寻呼/广播需一个读取派生调度的
  副作用投影器（不影响判定确定性）。
- 补传填平两段既有告警之间的空洞时，两告警保持独立（结论不回溯合并），
  交班视图中均可追溯。
- 角色由请求方声明；生产环境应改为从 mTLS 证书/令牌中解析。

## 环境备注

本工作区无外网直连，`dl.google.com` 与 `storage.googleapis.com` 被 egress
代理拦截。Go 工具链经 `deb.debian.org` 的 `golang-1.23` deb 包本地解压安装，
protoc 同理（`protobuf-compiler`）；Go 模块经 `proxy.golang.org` 获取
（`GOTOOLCHAIN=local` 防止工具链自举下载）。SQLite 驱动使用
`github.com/mattn/go-sqlite3`（CGO，系统 gcc）。
