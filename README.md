# 载人舱生命保障告警

本项目服务于载人飞行控制中心，处理舱压、二氧化碳和通风设备遥测产生的环境告警。

系统需要区分短暂尖峰与持续恶化，按照飞行阶段和角色提供可执行的处置信息，并保留确认过程。

## 架构

Go + gRPC + SQLite，事件溯源设计：

```
cmd/lifesupportd    服务入口（gRPC 服务器 + 升级心跳）
cmd/lsdemo          交班场景演示客户端
proto/lifesupport/v1  gRPC 契约（角色、判定结论、交班视图）
gen/                protoc 生成代码
internal/core       纯函数判定引擎（无 IO、无系统时钟，可确定性重放）
internal/store      SQLite 事件日志 + 派生状态（事务性应用、可重建）
internal/service    gRPC 服务层（校验、角色字段投影、交班视图组装）
```

### 判定模型

每条规则的判定同时参考六个因素：

| 因素 | 用途 |
| --- | --- |
| 设备采样时钟 | 持续窗口、证据链连续性、暴露时长 |
| 地面接收时刻 | 升级时限、确认/解除时标、传感器静默监测 |
| 持续窗口 | 区分短暂尖峰（TRANSIENT）与持续恶化（SUSTAINED_BREACH） |
| 关联传感器 | 必须在线且未滞后，否则结论只能是“证据不足” |
| 任务阶段 | 阶段覆盖限值（如 EVA 期间 CO2 黄限放宽） |
| 阈值版本 | 每次判定记录所用版本；版本不可变 |

**单个传感器失联只能标记证据不足**（INSUFFICIENT_EVIDENCE），系统绝不因数据缺失
推断环境安全：主传感器滞后、关联传感器缺失/滞后都得到该结论；未决告警在证据
不足期间保持打开，只有遥测证实恢复正常（持续满恢复窗口）或人工追加解除证据
才能解除。

### 事件溯源与确定性重放

- `events` 表是唯一事实来源；采样、阈值版本、任务阶段、确认、解除证据、心跳
  都是追加式事件，每个事件在一个事务内完成“记录日志 + 更新派生状态”。
- 派生状态（告警、判定记录、升级历史等）是事件日志的纯函数，
  `Rebuild()` 可随时从日志重建。
- 重复帧按 `(sensor, frame_id)` 去重，同序列不同取值记冲突并保留先到值；
  设备时钟回退用单调包络校正，不制造伪间隔，漂移计入传感器健康。
- 离线补传按原始采样序列归并：补传到达后在主传感器最新设备时刻重新判定，
  完整证据链得到结论；已记录的判定结论不改写。
- 旧阈值重放不改变当时结论：判定按窗口设备时刻选取当时生效的阈值版本，
  告警记录开启时的版本，判定记录逐条留存版本号。
- 进程中断只会回滚未完成事务；重投同一事件流（含时钟漂移、重复帧）后，
  未决告警、升级历史与确认人稳定重建（有测试覆盖）。

### 交班视图

`GetHandoverView(role)` 对每条告警解释：

- **由哪些采样形成**：证据采样链（传感器、设备时刻、取值、越过哪条限值）；
- **当前由谁接管**：确认人、角色、确认时刻及完整接管历史；
- **距离下一次升级还有多久**：下一级升级时刻与读取时计算的倒计时，
  升级历史（应到时刻、处理时刻、通知对象）完整可查。

三种角色各取履职所需字段：

- **乘组**：简述、处置建议、当前接管人、证据是否充分、解除进展；
- **飞控**：全部字段（证据采样、阈值版本、升级历史、确认历史、传感器健康）；
- **医学支持**：暴露统计（峰值/均值/越限时长）、证据取值、解除证据链、传感器健康。

### 不可变性

已确认的红色告警不可删除，只能追加解除证据；实际上所有告警都是只增不改的
审计记录，`DeleteAlert` 一律返回 `FAILED_PRECONDITION` 并说明原因。
遥测证实恢复时由系统以 `system` 身份自动追加解除证据。

## 运行

```bash
go build ./cmd/lifesupportd
./lifesupportd -db lifesupport.db -addr :50051 -heartbeat 10s
```

首次启动自动注册内置在轨默认配置（`v1-on-orbit`，CO2/舱压/风扇三条规则 +
分级升级策略）；之后可用 `RegisterThresholdVersion` 注册新版本、
`SetMissionPhase` 切换任务阶段。

演示（另开终端）：

```bash
go run ./cmd/lsdemo -addr localhost:50051
```

## 测试

```bash
go test ./...
```

覆盖：尖峰 vs 持续越限、证据不足（主/关联传感器失联）、间隔与坏值中断证据链、
时钟漂移、重复帧与冲突、幂等提交、离线补传归并、阈值版本不可变与版本钉死、
任务阶段覆盖、升级时刻表、确认移交、解除证据只增不改、三角色字段投影，
以及含进程中断的事件流重放确定性（`TestRebuildIsDeterministic`）。

## 重新生成 gRPC 代码

```bash
protoc -I proto -I <protobuf-include> \
  --go_out=gen --go_opt=paths=source_relative \
  --go-grpc_out=gen --go-grpc_opt=paths=source_relative \
  proto/lifesupport/v1/lifesupport.proto
```
